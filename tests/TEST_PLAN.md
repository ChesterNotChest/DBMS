# DBMS 测试计划

## 1. 测试计划

### 1.1 测试策略与目标

本项目测试采用“单元测试 + 集成测试 + 压力与性能测试 + 功能测试”的组合策略。单元测试用于验证 parser、service、repo、client 等基础模块的局部正确性；集成测试用于验证从客户端 SQL 输入到 service 和 repo 落盘的完整链路；压力与性能测试用于验证多客户端、大批量数据、索引构建与查询等场景下的稳定性和性能表现；功能测试用于从系统能力角度确认核心 DBMS 功能是否完整可用。

测试总体目标如下：

| 目标 | 说明 |
| --- | --- |
| 正确性验证 | 验证 DDL、DML、查询、约束、索引、认证权限等功能结果正确。 |
| 异常路径验证 | 验证非法 SQL、坏 payload、约束冲突、权限不足、锁冲突等失败路径能被明确拒绝。 |
| 一致性验证 | 验证数据文件、元数据、索引文件和缓存状态在成功或失败路径下保持一致。 |
| 并发与稳定性验证 | 验证多客户端、多线程、锁冲突和批量数据场景下系统不会出现状态污染。 |
| 性能数据产出 | 通过 CSV 记录不同规模下的耗时数据，为性能报告图表提供输入。 |

## 6. 运行方式

全量测试：

```powershell
$env:QT_QPA_PLATFORM='offscreen'
$env:PATH='E:\Qt\6.9.2\msvc2022_64\bin;' + $env:PATH
.\build\codex-vs-debug\Debug\DBMS.exe --run-tests
```

生成性能 CSV：

```powershell
$env:QT_QPA_PLATFORM='offscreen'
$env:PATH='E:\Qt\6.9.2\msvc2022_64\bin;' + $env:PATH
$env:DBMS_PERF_CSV_PATH='E:\Qt-projects\DBMS\build\performance_samples.csv'
$env:DBMS_STRESS_ROW_COUNTS='50,100,200,500'
.\build\codex-vs-debug\Debug\DBMS.exe --run-tests
```

临时跳过压力测试：

```powershell
.\build\codex-vs-debug\Debug\DBMS.exe --run-tests --skip-stress-tests
```
